# 智能供应链管理平台

面向食材采购与配送企业的一体化业务管理系统。项目以销售订单为业务起点，贯通客户管理、供应商报价、智能比价、采购下单、进货退货、库存查询、扫码分拣、配送跟踪、财务核算和经营分析，并通过企业微信接收客户下单与投诉消息。

> 项目名称：嘉采供应链管理平台<br>
> 前端：Vue 3 + Element Plus<br>
> 后端：FastAPI + SQLAlchemy<br>
> AI：OpenAI-compatible API / DeepSeek<br>
> 数据库：SQLite（开发环境），可切换 MySQL

## 项目亮点

- 覆盖食材配送企业从销售、采购到仓储配送和财务结算的完整业务链路。
- 商品支持多单位及换算率，可分别维护销售价和参考进价，并统一换算后进行供应商比价。
- 支持商品通用别名和客户专属菜名，提高人工录单及企业微信订单识别准确率。
- 销售单可一键转采购，按商品或品类快捷分配供应商，并标记当前最优报价。
- 企业微信客户消息可自动识别为订单、投诉或待人工处理消息，订单可生成销售草稿。
- 库存模块支持自然语言、商品、品类、规格、批次、临期及过期查询，并可上传 Excel 更新数据。
- 扫码分拣为客户和商品生成唯一任务码，支持分拣员、配送员移动端查看进度及扫码确认。
- 财务看板关联销售、采购和验收数据，统计销售额、验收金额、开票金额、加补金额及毛利。
- 基于角色和细粒度权限控制菜单与接口，财务权限默认不向任何角色开放。

## 核心业务模块

### 1. 基础资料与权限

- 供应商档案：新增、编辑、启用、禁用及批量删除。
- 商品分类：分类维护，并与商品新增、筛选和批量分配关联。
- 商品档案：名称、SKU、规格、别名、客户专属别名、保质期、保存温度、损耗率、质检报告等。
- 多单位管理：为同一商品配置多个单位、换算率、销售价和参考进价。
- 账号与权限：支持管理员、采购员、订单员、仓管员、供应商等角色，并可独立配置功能权限。

### 2. 供应商报价与智能比价

- 一个商品可绑定多个供应商，支持按品类或商品批量分配。
- 已分配的“供应商 + 商品”组合自动去重，避免报价页面出现重复商品。
- 供应商可按不同单位录入和批量保存报价。
- 系统将报价换算为基础单位价格，计算最低价、价差和供应商优势品类。
- 可接入兼容 OpenAI 协议的大模型，结合真实报价数据生成采购建议。

### 3. 销售与采购协同

- 销售单支持客户、配送日期、商品、规格、数量、价格及备注的快捷录入。
- 同一客户同一配送日期的加单可合并到已有销售单，分拣配送任务同步更新。
- 销售单可一键生成采购需求，再按商品快速选择不同供应商。
- 采购单支持按供应商批量选择商品、显示报价及最优价，并可编辑、确认和打印。
- 采购报表可下载为 Excel 或图片。

### 4. 企业微信订单助手与投诉管理

- 接入微信客服回调，保存客户身份、消息和会话信息。
- 将微信客户绑定到系统客户，可关联负责订单员。
- AI 将自然语言消息拆分为订单项、投诉或需要人工处理的内容。
- 支持相对日期识别，例如“后天送 10 斤火龙果”。
- 系统中暂无商品的内容也可保留在订单草稿，供采购或订单员后续补充。
- 食品安全投诉进入投诉专栏并按 P0、P1、P2 分级，未解决事项在工作台提醒。
- 可选语音转文字服务，识别客户语音中的下单与投诉内容。

### 5. 库存、进货与退货

- 上传标准 `.xlsx` 库存表并校验必要字段。
- 支持商品、品类、规格、批次和货物状态检索。
- 支持直接选择多个库存品类，或使用“油类库存”等自然语言查询。
- 自动识别临期、指定天数内到期及已过期商品。
- 显示商品条目、库存合计、零/负库存、批次数和 30 天内到期数量。
- 支持进货单、进货明细及进货退货单，记录供应商、批次、生产日期、保质期和入库位置。

### 6. 标签、扫码分拣与配送

- 普通标签与分拣任务标签分离，只有分拣任务标签包含二维码。
- 支持多种标签纸尺寸，以及客户、商品、数量、生产日期、保质期和配送日期等字段。
- 分拣员和配送员通过移动端入口查看本人任务，并通过工作 PIN 完成身份校验。
- 每个任务商品使用唯一扫码编码，防止不同客户或商品之间串码。
- 监控看板展示人员工作量、完成进度、单品处理时间及单个客户耗时。

### 7. 销售汇总与财务管理

- 销售看板按时间展示客户销售金额、订单时间、制单人及订单明细。
- 支持按客户、供应商、商品、商品分类、订单员、分拣员和配送员汇总。
- 汇总结果可筛选、预览并导出 Excel。
- 财务模块统计销售金额、预定金额、配送金额、验收金额、开票金额、加补金额、销售毛利、订单数和客户数。
- 支持销售商品金额、毛利及数量排行。
- 验收数量与配送数量可独立维护，并记录正常损耗、少送等差异原因。

## 业务流程

```text
客户/企业微信下单
        ↓
销售草稿 → 销售单 → 供应商分配 → 采购单
        ↓                     ↓
分拣任务/标签            进货与退货
        ↓                     ↓
扫码分拣 → 配送 → 实际验收 → 财务结算与经营分析
```

## 本地运行

### 环境要求

- Python 3.11+
- Node.js 20+
- npm 10+

### 启动后端

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

默认使用 SQLite，首次启动时自动创建数据表。API 文档地址：<http://127.0.0.1:8000/docs>。

### 启动前端

```bash
cd frontend
npm install
cp .env.example .env.development
npm run dev
```

访问 <http://localhost:5173>。开发模式下 Vite 会将 `/api` 代理到后端 `8000` 端口。

复制 `backend/.env.example` 为 `backend/.env`，按实际环境填写。以下只展示变量名，请勿把真实值提交到 Git：

```env

# 企业微信客服

# 可选语音识别
```

`SKIP_LOGIN=true` 仅适合本地调试。生产环境必须关闭免登录、修改默认账号密码，并配置足够强度的 `JWT_SECRET_KEY`。

## 库存文件格式

库存数据文件不会上传到 GitHub。运行后可在“库存查询”页面上传 `.xlsx` 文件，必要字段如下：

- 商品名称
- 品类
- 规格
- 总数量（最小单位）
- 整件数量
- 散装数量

可选字段包括入库、出库、退货、批次、生产日期、保质期、到期日、剩余天数和货物状态。

## 多单位比价规则

每个商品设置一个基础单位，基础单位换算率为 `1`；其他单位填写相对基础单位的数量：

```text
基础单位：件，换算率 1
辅助单位：箱，换算率 12
供应商报价：120 元/箱
基础单位价格：120 ÷ 12 = 10 元/件
```

系统以基础单位价格比较不同供应商，避免“箱、件、斤”等单位不同导致价格不可比。

## 企业微信接入

在企业微信管理后台启用微信客服 API，并将回调地址配置为：

```text
https://your-domain.example/api/wecom/callback
```

回调 Token、EncodingAESKey、企业 ID 和 Secret 只保存在服务器 `.env` 中。配置完成后，可在“企业微信订单助手”查看接入状态、客户绑定、原始消息、订单草稿和投诉记录。

## 微信商家订货小程序

`mini-program/` 是原生微信小程序，可直接使用微信开发者工具导入。小程序商品、图片、单位价格和客户专属名称来自后台商品管理；商家通过客户编号和预留手机号绑定，下单后直接生成销售单，同一客户同一配送日的加单自动合并，并继续联动采购、仓库、分拣和财务。正式发布需要已备案的 HTTPS 域名，并在微信公众平台配置合法请求域名。具体步骤见 `mini-program/README.md`。

## 生产部署建议

1. 使用 Nginx 托管前端静态资源，并将 `/api` 反向代理到 Uvicorn。
2. 使用 systemd、Supervisor 或容器编排工具守护后端服务。
3. 生产数据库建议使用 MySQL 或 PostgreSQL，并建立定时备份。
4. 关闭 `SKIP_LOGIN`，替换默认密码和 JWT 密钥。
5. 为企业微信回调配置 HTTPS 域名和有效证书。
6. 对质检报告、库存文件和数据库进行独立持久化与访问控制。
7. 根据实际域名配置 CORS、Nginx 请求大小和接口限流。

## 数据与密钥安全

仓库已忽略以下运行数据，不会随代码上传：

- `.env` 及各环境私密配置
- SQLite/MySQL 本地数据库文件
- 库存 Excel 和业务导出文件
- 商品质检报告及其他上传文件
- 日志、虚拟环境、前端依赖和构建产物
- 私钥、证书及常见凭据文件

提交代码前仍建议使用 GitHub Secret Scanning 或其他密钥扫描工具再次检查。
