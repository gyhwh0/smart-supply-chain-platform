# 餐饮配送 ERP 产品与工程准则

## 一、目标与边界

嘉采的目标不是复制竞品全部菜单，而是让 20 人左右的食材配送团队可靠完成：客户下单、订单审核、以销定采、收货入库、称重分拣、配送签收、客户验收、开票对账和经营分析。

产品判断优先级：

1. 食品安全与可追溯；
2. 金额、数量、库存和毛利准确；
3. 现场操作快、少点、少错；
4. 单据与岗位责任清楚；
5. 可维护、可扩展、可部署；
6. 最后才是界面效果和功能数量。

## 二、竞品公开能力分析

### 1. 利客

公开资料显示，利客强调生鲜专属进销存与财务、多单位、非标品成本、拍照/Excel/文字录单、频繁改单、AB 账、分仓、司机轨迹、农残检测、电子秤分拣、自定义打印、客户差异化商品名称及可见商品等能力。

值得吸收的产品原则：

- 生鲜不是普通标准品电商：称重差异、损耗、频繁改量和客户验收是核心数据。
- 打印模板、电子秤和现场分拣效率属于主流程，不是附属功能。
- 客户差异化必须贯穿商品名称、价格、菜单顺序、报表和打印。
- 成本不能只取“最后一次采购价”，要能解释批次、损耗和多次采购形成的成本。

### 2. 中用软件

中用公开资料强调多端订单、AI 语音/拍照录单、以销定采、智能预警、分拣责任与损耗、配送排线和温控、多仓调拨、价税分离、发票、对账、成本核算、溯源与经营报表，并突出“模块化、轻定制、柔扩展、通财务、全链路”。

值得吸收的产品原则：

- 功能必须按订单链路贯通，不能形成采购、仓库、财务各自一套孤岛数据。
- 中大型客户关注轻定制和模块化，核心数据模型应稳定，个性差异尽量通过配置、规则和模板实现。
- 上线不等于交付结束，岗位培训、试运行、数据初始化和异常处理手册同样属于产品。

### 3. 观麦/众道及其他系统

公开资料普遍覆盖订单、采购、分拣、仓储、配送、数据报表，并进一步强调 PDA、多人盘点、供应商/客户对账单、账期、成本费用分摊、物流跟踪、移动端经营看板及财务凭证。

共同趋势：

- 客户自主下单与订单员代客下单并存；
- AI 负责提效，但结果进入可审核业务单据；
- 电子秤、PDA、标签和小票打印与系统任务实时回写；
- 业务、财务、税务和溯源逐步合并为一条数据链；
- 管理者需要异常预警，而不只是静态汇总。

以上结论来自厂商公开介绍，属于产品能力口径，不代表对实际交付质量的独立验证。

## 三、嘉采当前定位与差异化

嘉采目前已具备商品多单位、客户专属名称、供应商报价与比价、销售转采购、企业微信智能订单/投诉、小程序下单、进货退货、库存、标签、扫码分拣、配送监控、验收、财务汇总和删除审核等基础。

适合形成的差异化不是“大而全”，而是：

- 企业微信、小程序和后台订单统一进入同一销售单领域服务；
- 未知商品、自然语言日期、订单与投诉混合消息可拆分并人工闭环；
- 客户专属菜名、商品可见范围、多规格销售价和加单合并贴近食配实际；
- 采购比价、供应商分配与销售需求直接关联；
- 分拣二维码、岗位任务和耗时监控适合小团队精细管理。

## 四、标准业务链路

```text
客户合同/价格方案
        ↓
客户下单（小程序/企微/订单员/导入）
        ↓
销售订单审核 ── 加单/改单/缺货/替代
        ↓
库存可用量与在途量净算
        ↓
采购需求 → 供应商分配 → 采购订单
        ↓
到货验收 → 批次/质检 → 入库或以拣代收
        ↓
波次/客户分拣 → 称重实配 → 标签/装车
        ↓
配送路线 → 签收 → 客户验收/退货/投诉
        ↓
应收应付 → 开票 → 对账/核销 → 毛利分析
```

每个环节均需保存来源单、目标单、操作人、时间、状态和差异原因。

## 五、后续需求的产品评审模板

每个新需求至少输出以下内容：

| 项目 | 必答问题 |
| --- | --- |
| 业务价值 | 减少什么错误、时间、损耗或资金占用？ |
| 使用岗位 | 谁发起、谁复核、谁最终负责？ |
| 前置条件 | 哪些基础资料、价格、权限或硬件必须先配置？ |
| 单据状态 | 草稿、已确认、执行中、完成、作废如何转换？ |
| 数据口径 | 数量、价格、成本、税额、时间以什么为准？ |
| 上下游联动 | 哪些单据、库存、任务、报表和提醒需要更新？ |
| 反向流程 | 如何加单、改单、退货、冲销、驳回和恢复？ |
| 并发幂等 | 重复点击、多人操作、回调重推如何处理？ |
| 权限审计 | 谁可看/改/审，是否保留变更记录？ |
| 验收方式 | 正常、异常、性能和数据结果如何测试？ |

## 六、20 人规模的工程验收标准

### 性能目标

- 20 个虚拟用户持续 5 分钟混合访问；
- 普通查询/保存 P95 小于 2 秒；
- 大型汇总/导出 P95 小于 10 秒，超过时转异步任务；
- 错误率低于 1%，不能出现重复单、库存越扣越多或金额丢失；
- AI/语音外部服务不可用时，核心手工业务仍可继续。

### 重点压测场景

- 订单员同时录入/修改销售单；
- 客户小程序与企业微信同时下单；
- 采购员批量转采购并保存供应商分配；
- 多名分拣员同时扫码、称重和完成客户任务；
- 财务汇总与日常开单并发执行；
- 企业微信重复回调、客户端重复提交和弱网重试。

### 当前生产环境判断

当前服务器为 2 核、约 1.6 GiB 内存、MySQL、单 Uvicorn worker。对于 20 人轻量 CRUD 具备基础可用性，但在 AI、语音、大 Excel、图片报表和多人大汇总并发时余量有限。不要仅通过增加 worker 解决问题：内存偏小，且每个 worker 都会增加数据库连接与应用内存。应先拆慢任务、优化查询和连接池，再以压测数据决定使用 1–2 个 worker 或升级到 2–4 GiB 内存。

## 七、近期产品与工程路线

### P0：上线安全和数据可信

- 关闭生产 `SKIP_LOGIN`，启用真实登录、HTTPS、强密钥和登录限流；
- 数据库自动备份、恢复演练、错误监控和审计日志；
- Alembic 数据库迁移及基础自动化测试；
- 销售—采购—库存—验收—财务关键金额对账校验；
- 20 人并发压测与慢查询治理。

### P1：完整业务闭环

- 客户合同、客户价格方案、账期和应收核销；
- 采购到货验收、供应商退货、应付对账；
- 批次库存、先进先出/临期策略、盘点和库存调整审核；
- 配送路线、装车复核、电子签收和退货；
- 食安溯源档案和客户侧追溯查询。

### P2：现场效率与规模化

- 电子秤/PDA/蓝牙打印设备适配层；
- 波次分拣、按区/按客户/按商品分播策略；
- 规则化价格、客户菜单、促销和缺货替代；
- 多仓、多组织和数据权限；
- 异常预警与老板经营驾驶舱。
